# Independent staff enquiries

Design intent: keep client staff able to handle genuine enquiries when the paid booking product is switched off. This page has only the client's Google sign-in and enquiry work. It has no agency account picker, appointments, receipts, payment controls or company switch. The page is a functional boundary; the separately requested dashboard visual overhaul remains outside this work.

Implementation spec: `/enquiries-studio` and its exact `/api/enquiry-studio/` assets/actions are independent of booking mode. The shared Google return address is `/api/studio/sign-in/callback`; the saved once-only attempt binds the destination portal. Only `client` + `signin` is accepted by the registered staff entry. Same browser, signed Google owner identity, expected client/origin, expiry and once-only consume/finish remain required. A booking attempt encountering OFF cannot exchange a provider code or issue a staff session. Resource consent and company password authority are separate.

The enquiry page reads only verified enquiry and enquiry-delivery items. Detail, note and retry actions reject booking/payment/delivery keys before storage. Its SQL authority independently checks the live client session, subject, client, origin and revocation, without granting booking authority. List pages use 50 records and the exact `next_cursor`; notes use a unique operation, expected review revision and a bounded 1,000-character single-line value. A queued retry never claims delivery. A lost response retains the action ID for retry, and the client checks the saved state. All customer content is rendered with text nodes.

The initial functional layout uses system fonts, 16px base text, 26px title and 18px detail titles; a 1,080px maximum width; 20px page gutters (14px below 580px); 12px gaps; 16px card padding; 12px card radii; and 14px button labels with 10px by 16px padding. Colors are `#18352e` text, `#f7f6f1` background, `#254d3e` buttons, `#d6dfd8` borders and `#b39d68` focus outlines. The message grid fits 300px minimum cards and collapses to one column on narrow screens. The page has status and sign-in first, messages/attention views, one detail area and explicit note/retry actions. CSP permits only the contained scripts/styles and same-origin calls; no frames, inline execution, forms or external resources.

Actual HTTP, RSA-signed synthetic Google responses and registered SQL-role proof: ten checks pass on owned disconnected PostgreSQL 16 and 18 in `/tmp/abs-staff106-16.log` and `/tmp/abs-staff106-18.log`. Chrome interaction proof, installed release equality and real hosted/account continuity remain pending. No production sign-in bypass or real provider call was added to obtain these results.

## Shared staff correction pass, 3 October 2026

The staff dashboard now uses the same zero-database display controller as public booking pages. It starts hidden, is revealed only by fresh ON evidence, and clears private displayed data when suspended or switched off. Company support and the independent enquiries dashboard retain their separately authenticated capabilities. The shared staff operation journal has installation/environment/purpose scope, explicit legacy readers and browser-origin write locks. Only random operation IDs and timestamps persist. New mutations wait for a verified storage write; blocked/corrupt storage never becomes a silent memory-only fallback. Unknown results are read from the server before a new change is permitted. Customer contact data, review notes and access codes are not written to browser storage.

Append-only SQL 021 provides role- and actor-bound recovery of closure/review outcomes. It does not return private notes or create another mutation. The enquiry-only route cannot expose booking review results while OFF. SQL 022 resolves local entered times using the current configured timezone and the same database conversion rules used for slots. Skipped daylight-saving times and changed timezone settings are rejected explicitly. Repeated times use the existing PostgreSQL standard-time preference. Calendar/rescheduling/company controls no longer append a fixed India offset. The month API is connected to date markers and selected-day details; broader visual redesign remains deferred.
