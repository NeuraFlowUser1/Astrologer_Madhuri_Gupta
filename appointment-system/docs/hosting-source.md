# Complete contained source preparation

`npm run prepare:hosting` invokes the installed `tools/install/source.mjs` launcher and `tools/install/source.py`. It prepares a new local directory and a checksummed file report beside it. It does not link an account, upload, deploy, install dependencies, read a credentials file, or call a provider.

The command needs Python with this package's declared dependencies. `BOOKING_SETUP_PYTHON` can select that interpreter explicitly; otherwise it uses `python` on Windows and `python3` elsewhere. Python imports come from this project's `appointment-system` directory.

`appointment-settings/hosting-files.json` is the reviewed website file list: version 1 and a `files` array of exact project-relative paths. Include website source, referenced public media, build/proxy helpers, host/dependency files and nonsecret appointment settings. Update the list when adding required website source. Existing asset names containing spaces remain valid; preparation does not rename them. Empty `.gitkeep` markers are unnecessary.

The full installed master is included automatically from its verified release manifest. Do not manually enumerate selected engine files. The tool checks the project Git root, exact contained entry point, project identity, source/destination release equality and every file checksum after copying. It refuses symbolic links, path traversal, changed inputs, missing files, unsupported file types, private path names and invalid manifests. An incomplete output is removed. A pre-existing sibling report is never overwritten or deleted.

This is an explicit source allowlist, not a universal secret scanner. The website file list must never contain account material or personal records. All protected settings remain in the hosting/provider secret stores. The prepared directory omits local `.env` files, Git history, dependency folders and unlisted operating artifacts. The complete installed package includes its portable checks and operating code so its manifest can still be verified after transfer.

Nineteen package/export methods passed locally, including source deletion, complete master inclusion, changed-source refusal, links, secret-name refusal, old-entry refusal and preservation of an unrelated report. Initial fixture/path-validation failures were corrected and are not counted as successful evidence. Both actual prepared websites subsequently built successfully. Both prepared backends started in fresh processes with factory/old-backend access and provider connections denied, asserted their own installation and release, refused a foreign Host, and denied booking pages while OFF. These are local build/startup checks, not a hosted or full customer-journey claim. The full evidence is in the programme’s 3 October operating-and-transfer review.
