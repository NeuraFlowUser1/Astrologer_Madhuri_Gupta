# Private staff inbox — implementation specification

29 September2026. P6 extension of the existing Studio, under the approved permanent-system plan. This is not a second admin application.

Design intent: let the practice read verified enquiries and see delayed/failed work without confusing human review with financial resolution or delivery success. Agency sees technical problems for its own record copies only; it gains no customer-message, booking or financial authority.

Implementation: two client views, Verified enquiries and Needs attention; agency receives Needs attention restricted to agency copies. Enquiries list only verified records, ordered by stable UUID,50 per page, details fetched explicitly. Issues derive from saved payment cases, booking/enquiry delivery obligations and adverse email observations; they are not a mutable green/red checklist. No customer contact, birth details, secret, raw provider payload or OAuth data in list results. Client-only detail returns enquiry content for responding through the approved practice channel. No automated staff email is introduced.

Each read checks exact Origin, request limits, authenticated role and a second session/identity check inside a fixed-search-path SECURITY DEFINER function. Revoke default PUBLIC execution. Expired/revoked sessions fail closed. Opaque source-prefixed cursors are bounded and validated; list limit50 plus one lookahead, stable unique keys. Snapshot changes can alter subsequent pages; Refresh starts over. No unbounded search by customer email/phone/reference.

Review notes are append-only, explicit actor/time/reason records, with operation UUID and expected per-item revision. Retrying an identical operation returns the same review; changed operation payload or revision conflict fails without mutation. A note never resolves a payment, resets provider uncertainty, restarts a send, cancels/reschedules an appointment or suppresses recovery. No financial or commercial policy is invented. Client notes attach only to currently owned enquiry/issue source; agency notes only to its own record-copy issues. No public receipt grants this authority.

UI values inherit existing Studio: paper#f4f0e8, panel#fffdf9, ink#263b32, forest#294d40; panel24px corners/32px padding, mobile24px; h2 24px, body16px, notes14px; controls48px/14px corners, focus3px# a76628. Bounded lists of bordered16px-radius rows, clear state/action sentence and optional Show details, no decorative motion around staff actions. Small screen320/390px; desktop1440px. No storage of customer data in browser persistent storage. Clear content on sign-out/access failure, invalidate in-flight reads, retain an uncertain review operation in memory only until the same request is checked or sign-out clears it.

Acceptance: role and database-session fences; expired/revoked session; hidden unverified enquiries; limit/cursor validation; literal text/XSS handling; distinct acknowledgement versus delivery; bounced accepted jobs still shown; review replay/conflict/revision; no financial mutation; role-switch/logout clears sensitive UI; desktop/mobile; unknown network result remains unknown. Development-only rollback fixtures and migration before production release. Provider/worker heartbeat and backup restoration evidence remain separate operational checks, not fabricated as database inbox health.
